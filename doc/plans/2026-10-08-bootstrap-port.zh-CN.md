# Toxee 完整引导功能移植计划

目标是在 DitMesh 中移植 Toxee `88f9e478` 的全部已实现引导功能：自动和手动节点配置、官方节点列表、真实 DHT 探测、桌面 LAN 节点启停，以及移动网络变化和前台恢复后的重引导。用户已在两个独立应用的批准架构下授权实施。

实现接口与模块分工见 [完整实施计划](2026-10-08-bootstrap-port.md)。界面只依赖 `ditmesh_chat_api` 中独立的 `NetworkBootstrapService`；原生调用、配置存储和网络引导实现放在 `ditmesh_chat`。保留当前原生固定版本 `093730ce` 及两个群聊修复补丁，所有模块不超过 500 行，保持 Morse-only 输入行为。

官方数据源为 `https://nodes.tox.chat/json`。初次启动立即使用已核验的四个数字 IP 节点，后台刷新列表，不用 HTTP 阻塞启动。主机名通过带时限的异步解析转换为数字地址后再进入原生接口。手动模式和 LAN 模式不引入公共节点。

桌面 LAN 功能创建独立无界面的 DHT 实例，使用实际绑定的 UDP 端口、公钥和局域网地址。启动前保存原节点，失败回滚，停止时恢复；异常退出后在原生聊天初始化前恢复。LAN 节点使用 DitMesh 独立的私有目录，不读取 Toxee 或 MorseCQ 数据。服务不自动启动，DHT 公钥每次启动可能改变。手机可手动使用 LAN 节点，不能托管桌面服务。

Toxee 的“扫描 LAN 节点”实际没有实现：只有未使用的数据类型和文案，没有按钮、广播循环或页面，来源测试文档 S92 也明确记录此事实。本次移植实际启停服务、完整可复制/分享的节点信息和手动连接，不增加扫描占位功能。

真实探测使用新的临时 Tox 实例，关闭局域网发现，只询问一个候选节点。结论区分节点响应、无响应、配置无效、设备无法使用 UDP、探测本身不可用，不能用参数被原生接受冒充节点可达。TCP 限制提示保持中性，不能把 UDP 探测当作 TCP 成功证据。

设置入口位于 Me、欢迎页和解锁页；手机展示自动/手动，桌面增加 LAN。节点列表支持刷新、在线状态、维护者、位置、上次探测和独立的测试/切换操作。手动配置修改任一字段即取消旧测试结果。十种语言均提供完整文案。

Android 和 iOS 使用 `ditmesh/network_path` 通道观察有效网络接口和地址。首次快照不触发；变化延迟三秒合并，三十秒间隔内保留一次尾随操作；离线取消、并发串行、会话销毁后不操作新账号。

按测试先行实施配置、探测、LAN 事务与恢复、网络变化、界面和生命周期。原生验证使用生产导出，检查真实 UDP 端口/DHT 响应、原生当前实例不变、子实例事件不污染用户连接状态。最终复跑现有原生测试与真实双进程单聊/群聊/重启/离线队列测试，运行应用分析和导入/文案/复杂度检查。协调 Dart/Flutter 独占窗口；提交、CI、图标、截图和最终文档由协调者统一整合。

## 独立复查后的探测隔离修正

保留原生 pin 和前两个群组补丁，在复制的构建源码中增加第三个局部 overlay `0003-isolate-private-node-probes.patch`。现有 headless 创建接口的有符号 `udp_start_port=-1` 专用于探测：关闭 LAN 发现，使用默认 UDP 端口范围，不安装 SDK/聊天全局监听器。普通 LAN 零/正数端口行为和 366 个导出函数保持不变。真实原生回归同时检查用户广播队列中没有子实例的 `conn:` 事件，及正在轮询的用户服务连接状态不受污染。LAN 失败回滚只有在旧节点实际恢复成功后才清除恢复日志。

自动和手动模式均展示当前保存节点的完整端点、公钥和直接测试按钮。自定义节点无需出现在公共目录中即可测试；节点变更会清除旧测试结果。窄屏、大字号和 RTL 回归覆盖这一展示与操作。
