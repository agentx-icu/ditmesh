# 引导节点与局域网托管

从**我的**进入网络设置；欢迎页或解锁页也可在打开身份前进入。节点配置属于本次安装，无需注册；切换身份会保留配置。

## 选择模式

| 模式 | 行为 |
|---|---|
| 自动 | 立即使用已保存的选择及数字地址备用节点启动（IPv4 地址，节点公布 IPv6 时一并使用，因此纯 IPv6 / NAT64 网络无需等待目录加载即可启动）；后台刷新官方 HTTPS 目录，应用多个有效在线节点。 |
| 手动 | 使用保存的主机、UDP 端口和公钥；公共目录刷新不会替换所选节点。所有平台均可在此配置局域网节点。 |
| 局域网托管 | 桌面运行独立 UDP/DHT 节点；将显示的地址、实际绑定 UDP 端口及完整 DHT 公钥分享给其他设备。 |

目录来自 [Tox 官方节点列表](https://nodes.tox.chat/)。网络或列表失败时显示备用数据状态。目录内 UDP/TCP 状态、维护者和位置属于发布方元数据；刷新、探测和选择是独立操作。

## 探测与配置

当前节点区域显示保存的地址、端口及完整公钥。自动或手动模式均可直接测试，公共目录中没有收录的保存节点也适用。

自定义节点填写主机、端口及 64 位十六进制 DHT 公钥，探测该组信息后应用。任一字段变化会使上次结果失效。IPv6 地址在列表中加方括号显示，主机输入框填写地址本身。主机名先异步解析并设置超时，再调用原生接口。

| 探测结果 | 含义 |
|---|---|
| 可达 | 该候选节点回应了真实 DHT 节点请求。 |
| 不可达 | 请求在探测期限内未获回应，或地址无法解析；检查地址、端口、公钥及网络路径。 |
| 信息无效 | 节点描述格式错误。 |
| UDP 不可用 | 本机 UDP 限制使探测无法进行；不能据此判定支持 TCP 的节点无法使用。 |
| 无法探测 | 独立探测实例未能运行，界面单独说明此限制。 |

每次探测使用临时原生实例并关闭本地发现，避免现有聊天或附近节点产生假阳性；聊天实例会保持原状。UDP/DHT 回应不能证明 TCP 中继可达。

## 托管局域网节点

在桌面选择局域网模式，填写首选 UDP 端口并启动。启动后使用显示的**实际**地址与端口；首选端口可能已被其他本地进程占用。复制或分享完整节点信息。同网设备在手动模式填入这些信息，Android/iOS 也适用。

iPhone、iPad 及 macOS 15 或更新版本需要局域网访问权限。请允许 DitMesh 的系统提示；若之前拒绝，在系统设置中开启后重新测试节点。权限用途说明已覆盖十种语言，详见 [Apple 局域网隐私文档](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)。

此处公钥属于托管节点的 DHT，添加联系人使用的 Tox ID 用途不同。托管实例使用与聊天身份分离的私有资料目录。启动、停止、启动失败和重启恢复会保留原公共节点配置。应用重启后需再次启动托管，并分享当前显示的信息。

其他设备正在使用该节点时，关闭前先停止托管。服务恢复原选择；恢复失败会保留恢复记录，允许重试。应用关闭会取消待处理的引导任务并释放自己创建的原生实例。

## 网络恢复

Android/iOS 网络路径变化及应用回到前台时触发带状态校验的重连；连续变化去抖，重复请求限流，身份会话或模式变化后停止旧任务。消息投递需要双方网络可达；离线消息保留在 DitMesh 的本地持久队列中。

聊天页待发送列表可查看历史中的排队和失败消息，取消排队发送或重试失败消息。投递详情随本地连接和对端在线状态更新。“已发送”只表示本地传输层接受，“已送达”需要真实对端回执；群聊只确认至少一名成员收到。回执不代表已读或已听。

兼容的 DitMesh 客户端可交换可选的原始拍发节奏，节奏记录也保留在本地队列中。其他客户端继续收到普通文字。群聊节奏记录通过私有通道作为可选元数据发送，文字回执不能证明节奏记录也已到达，详见[节奏协议](../rfcs/2026-10-09-keyed-rhythm.zh-CN.md)。

真实原生、界面及 CI 证据见[验证记录](../VALIDATION.zh-CN.md)。
