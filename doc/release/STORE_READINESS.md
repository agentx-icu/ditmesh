## Running the gates

```bash
# After the matching real-backend build, on that platform's host:
bash tool/ci/package_artifacts.sh --target macos --arch arm64 --mode validation
# Also: linux, windows, android, ios. Validation is the default mode.

# Android only: selected signing identity must be provided, no debug fallback.
# Set the four DITMESH_ANDROID_* key inputs in a secure environment, plus
# DITMESH_ANDROID_CERT_SHA256 to the owner's independently obtained certificate digest.
bash tool/ci/package_artifacts.sh --target android --mode distribution
```

Tags enforce the Android distribution-signing gate even without `--mode distribution`. CI uses four signing secrets (`ANDROID_KEYSTORE_BASE64`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEY_ALIAS`, `ANDROID_KEY_PASSWORD`) and repository variable `DITMESH_ANDROID_CERT_SHA256`. Partial signing configuration fails instead of silently choosing another key. APK cryptographic verification uses `apksigner`; AAB integrity uses the JDK `JarFile` verifier: every payload is read to EOF and must have one verified, currently valid leaf signing certificate. Its digest is checked against the APK and owner input. Android self-signed certificates are normal; disabled algorithms, tampered/unsigned entries, APK/AAB key mismatch, debug identity or missing/wrong expected identity fail. Ordinary `META-INF/services` resources are not exempt signing metadata. This single-signer contract requires an explicit reviewed update for multiple upload identities or key rotation.

Other platforms reject `--mode distribution` before packaging because their formal channel signing path is not implemented. This is a deliberate blocked state, not a store submission command. Ordinary tag draft packages on those platforms remain validation artifacts.

`native_payload.py` reads actual PE/ELF/Mach-O headers; Linux/Windows remain x64 and macOS uses its explicit target. Runner CPU, emulated tool ABI, native target, installed engine availability, package metadata and intended store target must be recorded separately. Renaming a directory/package cannot create target support. macOS seals nested code before its parent after the final mutation and verifies every code object's release entitlements. Ad-hoc verification never proves Developer ID, notarization or Mac App Store acceptance.

For Android, ELF PT_LOAD alignment applies to every packaged 64-bit native library; ZIP 16 KB placement applies to **uncompressed** `.so` entries. Check bundletool's AAB `PAGE_ALIGNMENT_16K` config and generated APKs before Play submission, then install the store/test-track build on a 16 KB device. The source NDK pin or a passing APK ZIP check alone does not prove the delivered AAB path.

Windows Flutter release bundles also contain the CPU-specific **ELF** Dart AOT snapshot `data/app.so`. This is documented by the pinned [Flutter AOT compiler](https://github.com/flutter/flutter/blob/3.41.9/packages/flutter_tools/lib/src/base/build.dart) and [Windows bundle target](https://github.com/flutter/flutter/blob/3.41.9/packages/flutter_tools/lib/src/build_system/targets/windows.dart). The packager explicitly enables this one path with `--flutter-windows-aot`; it still checks the ELF CPU against the PE app/engine target. Arbitrary foreign-format plugins and missing/wrong-CPU snapshots fail. The first Windows CI build exposed this format distinction; its downloaded runner's **17** runtime images pass the corrected inspector locally. Actual MSI generation/metadata checks still require Windows CI. Android signer parsing also distinguishes verified scheme/SDK-range labels from source stamps and requires exactly one current signer identity.

The [real Gradle AAB run on 2563e68](https://github.com/agentx-icu/ditmesh/actions/runs/39884174843/job/120189735884) built a 75.3 MB bundle and passed native alignment checks, then exposed a text-parsing failure: jarsigner listed manifest-last streaming warnings containing resource names such as `common_google_signin_btn_*_disabled.xml`; the old checker mistook `disabled` in those paths for a disabled signing algorithm. The replacement uses the [JDK JarFile API](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/jar/JarFile.html) for per-entry cryptographic verification instead of interpreting human warning text or applying streaming manifest-order assumptions. A signed manifest-last fixture includes that resource-name shape; tampered entries, unsigned additions and ordinary META-INF service entries still fail. The failed job did not upload its AAB; the regression fixture reproduces its ordering/name conditions and does not claim to be that real app bundle.

## X9 follow-up: exact-build symbols

Required native jobs build source-owned Release FFI code with debug information while preserving optimization, `NDEBUG`, architecture and release CRT. Symbols are stored outside runnable/native package directories. Cache entries include both binaries and symbols; restored bytes must pass the same pairing gate. `native-symbols-<target>` and `app-symbols-<target>` are separate **14-day Actions artifacts**, not additions to the public 12-asset release contract. A release owner must retain the matched artifacts with its supported release before Actions expiry; no new external storage or retention service is assumed.

| Output | Identity and evidence |
|---|---|
| Linux/Android source-built FFI; Linux native runner | Save DWARF before stripping. Require GNU build-id match, nonempty debug information, exact `.gnu_debuglink` basename/CRC and symbol content hashes. The actual optimized Linux fixture also resolves a known function and source line with `addr2line`. |
| Windows source-built FFI and native runner | Preserve `/O2`/release CRT and generate full PDBs separately. Require final PE RSDS GUID/age to match the archived PDB info stream, plus symbol content hashes. A real MSVC Release fixture exercises this on Windows CI. |
| Apple source-built FFI and native runner | Archive actual dSYMs and require every architecture UUID to match, plus DWARF compilation units and content hashes. iOS archive main symbols are matched independently against that archive's main executable; its embedded FFI must match the device FFI symbols. |
| Dart AOT | Each app build saves its own `--split-debug-info` output (APK/AAB and iOS archive have separate directories), exact Flutter engine revision/Dart version/target and final packaged AOT hashes. Cross-format UUID equivalence is **not** asserted. No obfuscation or runtime collection is introduced. See [Flutter symbolication guidance](https://docs.flutter.dev/deployment/obfuscate). |

Pairing reads the actual final ZIP, DEB, RPM, TAR, PKG, APK, AAB and unsigned IPA entries, not just source or staging directories. Installed/repaired MSI runner and FFI bytes are checked again; existing lifecycle and whole-payload equality gates remain required. iOS archive output has an additional exact main/dSYM and embedded-FFI check. Reports record final package/binary hashes. A failed or missing identity, symbol file, debuglink or required native entry stops the job. CI must execute these checks on the final PR head before this subset of X9 is considered verified.

For a matching Linux source address, use `addr2line -Cf -e <archived .debug> <module-relative address>`; Apple tools need the matching dSYM/architecture and image load address; Windows debuggers need the matching GUID/age PDB. Never substitute a newer build's symbols. A real device crash with readable application and native frames is still **needs device**, not proven by binary identity tests.

The artifacts cover source-generated FFI/runner and Dart outputs, not complete vendor symbols. Flutter 3.41.9 engine binaries (`flutter_windows.dll`, `libflutter.so`/`libflutter_linux_gtk.so`, `Flutter.framework`) require symbols from the **recorded engine revision and target** via the matching official Flutter SDK/engine artifacts or Flutter maintainer support; missing vendor PDB/dSYM/DWARF is an explicit external-material gap. Plugin/prebuilt codec/ML and vcpkg libraries need the corresponding `pubspec.lock`/vcpkg-pinned source or vendor release's exact matching symbols; build IDs/UUIDs/GUID-age must agree. OS frames require the device's exact OS build and its Apple/Microsoft/distribution symbol packages. This change neither fabricates these files nor claims that an app-owned symbol file covers them. Native crash collection and persistent/uploaded diagnostic policy remain separate decisions; existing log privacy fixes are tracked independently.
