# 首次通联试用：三对搭档

[English](FIRST_CONTACT_TRIAL.md)

目标是观察两个人能否互相连接，并完成真正的 CQ 与回复。本文件是任务脚本，不表示试用已经发生。

招募三对原本认识的搭档，观察前征得同意。使用 P01–P03 和设备 A/B 编号，不记录姓名、Tox ID、手机号或私人聊天。每人自行保管身份和备份，不收集密钥文件、密码、麦克风录音或未脱敏生产日志。参与和本地观察记录导出均为自愿；应用和官网不增加使用分析。

## 首次体验（约 15 分钟）

1. 记录两端应用版本/构建号、安装包 SHA-256、平台、安装/更新来源和网络类型，区分开发包、所有者签名包和商店交付。
2. 不提示操作路径，请两人创建或导入自己的身份并完成备份。出现意外身份或数据替换时停止。
3. 请 A 在“发给自己”中拍发 CQ、试听、发送并播放。询问“谁收到了消息？”正确理解应为仅此设备。
4. 请 A 通过下一步联系人入口进入既有 Tox ID/二维码流程，与 B 建立好友关系。B 明确接受申请。观察能否识别在线/离线。
5. A 向 B 拍发 CQ，记录发送时间和实际观察到的排队/发送/送达状态。B 播放后拍发 R，A 播放 R。只有收到这条真实回复才算往返完成，记录求助和放弃的位置。
6. 两人比较原始节奏与自己的速度。缺少原始时序时记录界面回退，不将合成播放标为发送方实际手法。
7. 请两人解释已排队、已发送、已送达。群回执只证明至少一位成员收到，不证明所有人都已收听。

## 网络与生命周期复测

仍使用同意参与的搭档和 CQ/R 等非敏感内容。升级前将身份备份保存在应用之外。

| 场景 | 观察内容 |
| --- | --- |
| 不同 Wi-Fi，再测 Wi-Fi 与蜂窝网络 | 真实对端连接、回执与回复耗时；本机回环另记。 |
| B 断网后重新连接 | A 显示的状态、待发记录保留、恢复后的回执、是否重复气泡/回复；没有确认的已发送不算成功。 |
| 一台手机锁屏或进入后台后返回 | 接收是否停止、提示是否清楚、返回前台或主动重试能否恢复；不假设存在推送服务或后台保证。 |
| 关闭并重启两端 | 历史、草稿、原始时序播放是否正确。 |
| 同一正式签名渠道覆盖上一版 | 身份、好友、历史和草稿保留；更换密钥或开发证书后的重装不算升级。 |

每对搭档复制一份 `first_contact_observation.template.json`。未执行的字段保留 null，状态保留 `not_run`。先记录事实再建议修复。本地文件默认私有，只有双方同意后才导出脱敏结果。建议目标是三对搭档都在作者不指导的情况下完成真实 CQ/回复；这只是目标，不是已有结果。
