# 原始拍发节奏 — 实现约定

DitMesh 的此实现替代此前提议的消息注解 RFC。固定 Tim2Tox 提交为 `31531dba67491a920609e2ea543e991c7c75f3c0`；依赖引导用 `tool/ci/tim2tox-dart-overlays` 中的补丁生成独立 Dart 包，不修改上游子模块。

## 节奏记录与保存

`KeyedRecording` 是版本 1 的正整数毫秒数组，交替表示按下与间隔，以按下开始和结束。数组长度为奇数，最多 511 段，总时长不超过 120 秒。无效或不支持的节奏记录会被丢弃，消息文字仍可使用。

编辑器在本地侧音开关之前采集按键转换，按解码 token 关联到共享的实时草稿。删除会移除相应 token 的时序，保留 token 之间的间隔仍反映实际经过的时间；采集过程本身也受上限约束。未采集/恢复的文字、不兼容的时钟或超出边界，会使原始回放不可用，清空草稿后恢复采集。这是时序元数据，不是音频文件录制。

`ChatMessage.recording` 和 `ChatService.sendText(recording:)` 向应用提供此数据，不暴露传输层类型。本地历史、权威发送队列及加密备份把节奏记录保存在消息元数据中；恢复后的待发送项也携带可选节奏记录。投递状态和节奏记录是否可用相互独立。

晚到的节奏事件带有本地 `ChatMessage.isUpdate` 注解，通知和自动播放不把它当作新消息；当前或暂存的气泡原位更新，不增加新消息计数。此注解不在线上传输，也不保留在备份中。

播放器按 Morse token 确定词位置，只有完整按下/间隔结构匹配时才使用原始时长；否则显示原始时序不可用，并按听者速度播放。接受的原始时长逐段替换生成时长，不做归一化。晚到记录更新已打开的播放器面板，不重启当前片段；明确重播后使用新的记录。

## 单聊

普通原生 C2C 文字不会把发送者生成的消息标识暴露给 Dart 接收端。按文字、先后顺序或相近时间关联节奏会混淆重复消息。兼容的双方因此协商与会话绑定的扩展，用一个封装传送文字、随机消息标识、内容类型与可选节奏记录。接收端以 `dmr:` 标识创建一条普通消息，先持久化再回执，并在重启后仍按此标识去重；不同标识下相同文字各自保留。

无法协商能力时继续使用现有普通文字发送路径。只有实际收到节奏记录才能原始回放。节奏记录封装的确认会更新原有消息的送达状态；认证发送者和当前发起者会话都必须匹配。

重复消息也需跨过历史保存屏障才能确认，缓存命中不能证明写入成功。失败后保留未发布状态，存储恢复后只发布一次到达；最多保留 128 项，达到上限时新接收在追加前拒绝。历史会话、清空代次和本地身份代次共同阻止旧任务跨身份发布或确认。

认证后的能力 hello 携带发送者当前会话。收到新的 hello 即刷新对端会话，即使本端未观察到短暂离线，旧挑战回执也不能使会话回退。不带会话字段的旧版本 1 hello 仍通过挑战/确认协商兼容。发送在等待协商后重新检查本端会话：退出账号取消在线发送，离线队列项则保留在磁盘。

## 原生群聊

NGC 始终发送原有普通文字，可选节奏记录按群聊 ID、认证发送者公钥及原生消息 ID（`gmid`）关联，通过现有群回执通道私发给当前在线成员。元数据可早于或晚于文字到达，附加节奏记录更新原有文字行。群文字回执确认至少一名成员收到，不能证明节奏记录也已到达。

## 控制载体与边界

扩展 JSON 封装在现有精确类型回执结构中，使用保留的 `dmr1:` 消息 ID 前缀。接收端在普通回执匹配、预览、未读计数和通知之前消费它。现有 Tim2Tox 回执处理器会消费无法关联的回执 ID；普通文字兼容路径和公共群文字保持不变。

封装最多 8 KiB，以 352 字节分块，含随机传输 ID、分块序号和总数。重组按认证发送者、会话和传输 ID 隔离，支持乱序；最多 24 块、32 个未完成重组，保留不超过 30 秒。冲突分块使该次传输失效；节奏记录在消息边界再次验证。

## 复现验证

在工作区根目录运行依赖引导及 API/后端测试。原生双端测试用 `packages/ditmesh_chat/test/helpers/run_real_peers.py` 和不含测试钩子的 `TIM2TOX_FFI_LIB`；Tim2Tox 每个进程只有一个单例，所以启动独立进程。场景覆盖单聊/群聊准确时长、相同文字不同标识、真实送达回执、加密重启、带节奏记录的持久队列排空及群重连。本 worktree 的验证结果与限制见[验证记录](../VALIDATION.zh-CN.md)。
